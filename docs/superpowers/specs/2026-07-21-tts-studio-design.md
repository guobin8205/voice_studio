# TTS Studio — 多模型语音合成调试 Web UI 设计文档

> 创建日期：2026-07-21  
> 状态：设计完成，待实施

---

## 1. 项目概述

### 1.1 定位

小团队内部工具，为 Qwen3-TTS、IndexTTS2、VoxCPM2 三个 TTS 模型提供统一的声音设计、声音克隆和自定义音色调试 Web 界面。

### 1.2 核心目标

- 统一三个模型的调试入口，降低切换成本
- 支持声音设计（提示词驱动）、声音克隆（参考音频驱动）
- 支持多模型横向对比，一键生成所有选中模型的输出
- 音色作为通用资产存储，不绑定特定模型
- 支持导出音色包供生产环境使用

### 1.3 用户角色

小团队成员（2-10 人），各自本地 GPU 运行模型，通过 Web UI 调用本机推理服务。

## 2. 技术架构

### 2.1 整体架构

```
浏览器 (React 18 + TypeScript + Vite)
  │
  │ REST API + WebSocket (推理进度/流式音频)
  ▼
FastAPI Server (Python)
  ├── REST API 路由层
  ├── Model Manager（按需加载/卸载，LRU 策略）
  ├── Audio Utils（ASR、音频处理）
  └── Model Adapters
        ├── Qwen3-TTS Adapter
        ├── IndexTTS2 Adapter
        └── VoxCPM2 Adapter
              │
              └── 统一的 ModelInterface 抽象
```

### 2.2 技术选型

| 层 | 技术 | 理由 |
|---|---|---|
| 前端框架 | React 18 + TypeScript | 复杂交互、组件复用、生态丰富 |
| 构建工具 | Vite | 快速 HMR |
| 样式方案 | Tailwind CSS 或 CSS Modules | 灵活，维护性好 |
| 状态管理 | Zustand | 轻量，适合中型应用 |
| 音频播放/可视化 | Wavesurfer.js + Howler.js | 波形可视化 + 播放控制 |
| 后端框架 | FastAPI + Uvicorn | 原生 async，自动 OpenAPI 文档 |
| 模型管理 | 自定义 ModelManager | 按需加载/卸载，LRU 策略 |
| 实时通信 | WebSocket | 推理进度推送、流式音频 |
| 音色存储 | SQLite + 文件系统 | 轻量，零配置 |
| ASR | Whisper (local) | 参考音频自动转写 |

### 2.3 模型管理策略

- 模型按需加载/卸载，避免同时占用 GPU 显存
- 每个模型封装为统一的 ModelInterface Adapter
- 切换模型时有 5-30 秒加载延迟，UI 显示加载进度
- 模型规格支持：1.7B / 0.6B

## 4. 核心概念

### 4.1 音色（Voice）

音色是**通用资产**，不绑定特定模型。分两种类型：

| 类型 | 存储内容 | 跨模型兼容性 |
|------|----------|-------------|
| **提示词音色** | 自然语言描述文本 | ✅ 所有支持 prompt 的模型通用 |
| **克隆音色** | 原始参考音频 + 各模型嵌入缓存 | ✅ 原始音频通用，嵌入按需提取 |

### 4.2 音色库记录结构

```json
{
  "id": "voice_001",
  "name": "温柔知性女声",
  "type": "prompt",           // "prompt" | "clone"
  "prompt": "温柔知性的女声，像深夜电台主播...",
  "reference_audio": null,    // 克隆音色才有
  "embeddings": {             // 克隆音色的嵌入缓存
    "qwen3tts_1.7b": "path/to/embedding.pt",
    "indextts2_1.7b": null    // null = 未提取，使用时自动生成
  },
  "params": { "speed": 1.0, "pitch": 0, "temperature": 0.4, "top_p": 0.9 },
  "created_at": "2026-07-20T10:00:00Z"
}
```

### 4.3 音色导出

导出为 zip 包供生产环境加载：

```
voice_001.zip
├── manifest.json       ← 元信息（名称/提示词/参数/来源/创建时间）
├── reference.wav       ← 原始参考音频（克隆音色才有）
└── embeddings/         ← 各模型缓存（可选）
    ├── qwen3tts.pt
    └── indextts2.pt
```

## 5. 页面详细设计

### 5.1 声音设计

**输入字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 语言 | 下拉 | 中文 / English / 日本語 / 한국어... |
| 方言 | 下拉（可选） | 普通话 / 粤语 / 四川话 / 上海话 / 闽南语... |
| 音色描述 | 多行文本（~150字） | 提示词，情绪融合其中 |
| 合成文本 | 多行文本（~200-300字） | 要说的内容 |
| 参数 | 滑块 | 语速 / 音高 / 温度 / Top-P |

**模型选择：** 多选复选框，每个模型可选规格（1.7B / 0.6B）

**输出：** 每个选中模型的生成结果卡片（波形可视化 + 播放 + 保存）

**保存行为：** 存储提示词文本，不存储模型输出。所有兼容模型可用。

### 5.2 声音克隆

**输入字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 语言 | 下拉 | 同声音设计 |
| 方言 | 下拉（可选） | 同声音设计 |
| 参考音频 | 文件上传 | 拖拽或点击，支持 wav/mp3/flac，建议 3-15s |
| 参考音频波形 | 播放器 | 上传后显示波形，可播放/暂停/拖动 |
| ASR 识别 | 多行文本（可编辑） | 自动转写参考音频内容，可手动修改 |
| 合成文本 | 多行文本（~200-300字） | 可一键填入 ASR 结果 |
| 情感 | 单行文本（可选） | 自由文本 |
| 音色名称 | 单行文本 | 保存到音色库的名称 |
| 参数 | 滑块 | 语速 / 音高 / 温度 |

**模型选择：** 多选复选框，每个模型可选规格（1.7B / 0.6B）

**输出：** 每个选中模型的克隆结果卡片

**保存行为：** 存储原始参考音频 + 各模型嵌入缓存。所有模型可各自提取嵌入。

### 5.3 调试台

**特有功能：**
- 从音色库加载已有音色（自动填充描述和参数）
- 每个模型可独立覆盖全局参数（⚙ 按钮）
- 输出标注参数来源（覆盖 vs 默认）

**输入字段：** 同声音设计 + 声音克隆的并集，加载音色库时自动填充。

**模型选择：** 多选，每行有「⚙ 覆盖参数」入口。

**输出对比：** 按模型分组展示，标注参数差异。

### 5.4 音色库

**功能：**
- 搜索：按名称、描述搜索
- 筛选：按类型（提示词/克隆）、兼容模型
- 卡片列表：显示名称、描述/参考音频、兼容性、嵌入缓存状态
- 操作：▶ 试听、🔬 加载到调试台、📦 导出、🗑 删除

**音色卡片信息：**

| 提示词音色 | 克隆音色 |
|-----------|---------|
| 📝 提示词文本 | 📁 参考音频文件名+时长 |
| ✓ 通用 · 所有模型可用 | 🧬 各模型嵌入缓存状态 |

## 6. 数据流

### 6.1 声音设计流程

```
用户输入提示词 + 文本 + 参数
  → 勾选模型 A、B
    → POST /api/generate { model: "A", prompt, text, params }
    → POST /api/generate { model: "B", prompt, text, params }
      → 各模型异步推理（WebSocket 推送进度）
        → 返回音频 + 波形数据
          → 前端渲染对比
            → 用户保存 → POST /api/voices { type: "prompt", prompt, params }
```

### 6.2 声音克隆流程

```
用户上传参考音频
  → POST /api/asr { audio } → 返回识别文本
    → 用户确认/修改文本
      → 勾选模型 A、B、C
        → POST /api/clone { model, audio, text, emotion, params }
          → 模型提取嵌入 → 合成
            → 返回音频
              → 用户保存 → POST /api/voices { type: "clone", audio, embeddings }
```

### 6.3 调试台流程

```
用户从音色库选择音色
  → GET /api/voices/{id} → 返回音色数据（提示词 or 参考音频 + 嵌入）
    → 自动填充输入区
      → 勾选模型 A、B、C
        → 为每个模型配置独立参数
          → 一键生成所有
            → 输出横向对比（标注参数差异）
```

## 7. API 设计概要

### 7.1 模型推理

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/generate` | 提示词驱动生成 |
| POST | `/api/clone` | 参考音频驱动克隆 |
| POST | `/api/asr` | 音频转文字 |
| WS | `/ws/progress/{task_id}` | 推理进度推送 |

### 7.2 音色管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/voices` | 音色列表（支持搜索/筛选） |
| GET | `/api/voices/{id}` | 音色详情 |
| POST | `/api/voices` | 创建音色 |
| DELETE | `/api/voices/{id}` | 删除音色 |
| GET | `/api/voices/{id}/export` | 导出音色包（zip） |

### 7.3 模型管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/models` | 可用模型列表及能力 |
| GET | `/api/models/{name}/status` | 模型加载状态 |
| POST | `/api/models/{name}/load` | 加载模型 |
| POST | `/api/models/{name}/unload` | 卸载模型 |

### 7.4 系统监控

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/system/status` | GPU 状态 + 当前模型 + 最近推理耗时 |
| GET | `/api/system/history` | 近期显存/耗时趋势数据 |

## 8. 非功能需求

### 8.1 性能

- 模型首次加载 5-30 秒，后续缓存命中 < 2 秒
- 单次推理（短文本 < 50 字）< 3 秒
- ASR 转写 < 2 秒
- 前端页面加载 < 1 秒

### 8.2 显存管理

- 同一时间只加载 1 个模型（LRU 策略）
- 空闲 15 分钟后自动卸载
- 提供手动卸载入口

### 8.3 性能与显存监控

服务端通过本地 API 采集 GPU 和模型运行状态，前端通过状态栏展示。

**采集指标：**

| 指标 | 来源 | 说明 |
|------|------|------|
| GPU 显存占用 | `pynvml` / `torch.cuda.memory_allocated()` | 已用 / 总量 |
| GPU 利用率 | `pynvml` / `nvidia-smi` | 百分比 |
| 当前加载模型 | ModelManager | 模型名 + 规格 |
| 模型加载耗时 | ModelManager 计时 | 上次加载花费时间 |
| 最近推理耗时 | API 中间件计时 | 每次推理的耗时记录 |
| 显存趋势 | 定时采样 | 最近 N 分钟的显存变化 |

**前端展示：**

- 侧边栏底部状态指示器（固定可见）
- 加载中：显示进度条 + 预估时间
- 就绪：显示模型名 + GPU 显存使用率
- 空闲：显示「无模型加载」+ 空闲时长
- 推理中：显示推理耗时 + 进度

**API：**

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/system/status` | GPU 状态 + 当前模型 + 最近推理耗时 |
| GET | `/api/system/history` | 近期显存/耗时趋势数据 |

### 8.4 错误处理

- 模型加载失败：显示错误提示 + 重试按钮
- 推理超时（> 60s）：自动取消 + 提示
- ASR 识别失败：显示原始音频，允许手动输入
- 磁盘空间不足：导出/保存前检查

## 9. 开发优先级

**Phase 1：基本推理全通**
- FastAPI 后端 + ModelManager + 三个 Model Adapter
- 基础 REST API（generate / clone / asr）
- React 前端骨架 + 侧边栏导航
- 声音设计页面（单模型 → 多模型）
- 声音克隆页面（ASR + 波形播放器）

**Phase 2：音色管理**
- 音色库 CRUD API
- 音色库页面（搜索/筛选/卡片列表）
- 保存音色功能（设计 & 克隆）
- 音色导出 API

**Phase 3：调试台 + 对比**
- 调试台页面（音色库加载 + 多模型对比）
- 每模型独立参数覆盖
- WebSocket 进度推送
- 生成历史记录

**Phase 4：打磨**
- 错误处理完善
- 模型加载状态 UI
- 性能优化
- 文档
